# TTS bake-off: Kokoro (current) vs Paradee

Paradee ([sahilmahendrakar/Paradee-8M-v1.0](https://huggingface.co/sahilmahendrakar/Paradee-8M-v1.0), Apache-2.0) distills
Kokoro-82M into an 8M-parameter, single-voice model (Kokoro's `af_heart`; 9 MB int8 ONNX). Question: could it replace Kokoro
in the assistant to save memory and CPU?

**Verdict: not worth switching now.** Faster and just as intelligible, but it does not save real memory, it changes the voice,
and it needs a different Python environment. Details below.

## Results (10 typical assistant replies, `sentences.txt`, Apple M4 16 GB, nothing else heavy running)

| Engine / voice | Speed | Short-phrase latency | Process memory | Intelligibility (WER, lower is better) |
|---|---|---|---|---|
| Kokoro `am_fenrir` (**the assistant's current voice**) | 4.3x real time | 450 ms | 0.66 GB | 4.7% |
| Kokoro `af_heart` | 4.3x | 481 ms | 0.71 GB | 4.1% |
| Paradee int8 (`af_heart` only), 1 CPU thread | **17.7x** | **131 ms** | 0.54 GB | **3.5%** |

- **Intelligibility** = each clip is transcribed with the same Whisper model the assistant uses (`base.en`) and compared with the
  input text. Absolute WER is inflated by formatting (Whisper writes "$389", the reference says it out loud), so only compare
  rows. All three are within about 1 point, which on 170 words is 2 words: effectively equal.
- **Memory is not a big win.** Paradee's own model session adds only about 0.08 GB, but its text-to-phoneme step (`misaki` + spaCy)
  adds about 0.37 GB, so the whole pipeline is about 0.5 GB versus Kokoro's 0.63-0.68 GB. The "9 MB" headline leaves the
  phonemizer out.
- **The voice changes.** Paradee has one voice (`af_heart`, female). The assistant is set to `am_fenrir`.
- **It does not run in the project's Python.** `misaki` requires spaCy, which has no build for Python 3.14 (the project's version).
  The test used a throwaway Python 3.12 environment from `uv`. Integrating it would need that or a different phonemizer; the
  model was trained on misaki phonemes, so swapping in espeak phonemes would likely hurt quality (not tested).

## Not measured

- **Subjective quality (how it actually sounds).** Only a human ear can judge that. Samples are generated by the scripts into `/tmp/tts_samples/`
  (`afplay /tmp/tts_samples/paradee_int8_07.wav`). The Paradee paper reports UTMOS 4.41 vs Kokoro 4.52; I did not verify that.
- Paradee fp32, multi-thread Paradee, Kokoro with a single thread (Kokoro ran with onnxruntime's default threads, so the CPU
  comparison is not strictly like for like), cold-start load time (the first Paradee run included the one-time model download).

## Reproduce

```bash
./.venv/bin/python benchmarks/tts_eval/bench_tts.py kokoro --voice am_fenrir     # also: --voice af_heart
mkdir -p /tmp/paradee_ref && curl -L https://raw.githubusercontent.com/sahilmahendrakar/paradee/main/paradee/tts.py -o /tmp/paradee_ref/paradee_tts.py
uv run --no-project --python 3.12 --with "misaki[en]" --with espeakng-loader --with phonemizer-fork --with onnxruntime \
  --with huggingface_hub --with numpy --with soundfile \
  --with "en_core_web_sm @ https://github.com/explosion/spacy-models/releases/download/en_core_web_sm-3.8.0/en_core_web_sm-3.8.0-py3-none-any.whl" \
  python benchmarks/tts_eval/bench_tts.py paradee
./.venv/bin/python benchmarks/tts_eval/wer.py /tmp/tts_samples base.en
```

Revisit if `misaki` drops its spaCy dependency (so the phonemizer gets light) or Paradee ships a multi-voice version.
